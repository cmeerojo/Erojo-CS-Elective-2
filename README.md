# JDM Showroom

A Flutter + Supabase showroom for browsing Japanese domestic market cars.
The app uses Riverpod for showroom state, price filtering, loading/error
states, and pagination. Each Supabase request returns at most eight cars.

## Supabase setup

Create a `jdm_cars` table:

```sql
create table public.jdm_cars (
  id bigint generated by default as identity primary key,
  make text not null,
  model text not null,
  year integer not null,
  price numeric(12, 2) not null check (price >= 0),
  mileage integer not null default 0 check (mileage >= 0),
  transmission text not null,
  image_url text,
  description text
);
```

Grant the app's client role read access according to your authentication
policy. Add a `.env` file in the project root:

```text
SUPABASE_URL=https://your-project.supabase.co
SUPABASE_ANON_KEY=your-publishable-key
```

The app intentionally treats `.env` as optional so it never renders a blank
page when configuration is missing. Instead, the showroom displays a
configuration error and a Retry button. Once configured, the service sends
`gte('price', minPrice)`, `lte('price', maxPrice)`, and `range(start, end)` to
Supabase. Riverpod owns the active price range and page.
